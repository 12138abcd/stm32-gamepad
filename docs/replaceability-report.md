# 国产 MCU 可替代性评估报告
## STM32F103C8T6 → GD32F103C8T6

> **本报告的定位**：回答"**能不能替代、代价多大、值不值得、风险在哪**"。
> **实验过程与原始数据**见配套文档 [`porting-report.md`](./porting-report.md)（本报告只引用其结论）。
> **评估日期**：2026-10-07
> **评估结论**：✅ **可替代性：高** —— 迁移成本 **1 行代码**，功能与性能**无退化**。

---

## 1. 背景与动机

### 1.1 为什么评估国产替代

* **供应链单点风险**：单一供应商在缺货周期内交期与价格波动剧烈，硬件产品会直接受到牵连；
* **成本与交期**：同类国产器件通常具备价格与交期优势（⬜ 具体报价待补，见 5.2）；
* **产业趋势**：消费电子与工业产品对国产化替代的接受度持续提高。

### 1.2 本项目场景

| 项 | 内容 |
| --- | --- |
| 产品 | USB HID 游戏手柄（消费电子 / 智能硬件） |
| 原平台 | **STM32F103C8T6**（ARM Cortex-M3，72 MHz） |
| 候选替代 | **GD32F103C8T6**（ARM Cortex-M3，**Pin-to-Pin 兼容**） |
| 固件规模 | 自研模块 5 个（按键扫描 / 摇杆映射 / 报告 / 延迟探针 / 主循环）+ ST USB 中间件 |

### 1.3 评估范围

* **在范围内**：主控迁移的硬件改动、软件改动、功能与性能一致性、迁移风险；
* **不在范围内**：无线（2.4G）通路、≥72 h 长期老化（列为遗留项，见 8.4）。

## 2. 替代方案概览

| 项 | STM32F103C8T6 | GD32F103C8T6 | 兼容性 |
| --- | --- | --- | :---: |
| 内核 | ARM Cortex-M3 | ARM Cortex-M3 | ✅ 相同 |
| 封装 / 引脚 | LQFP48 | LQFP48 | ✅ **Pin-to-Pin** |
| 外部晶振 | 8 MHz | 8 MHz | ✅ 相同 |
| 主频（本项目使用） | 72 MHz | 72 MHz | ✅ 相同 |
| 主频上限 | 72 MHz | **108 MHz** | ➕ GD 有余量（本项目未启用） |
| 开发工具 | Keil MDK 5.38 + ARMCLANG | 同一工程直接复用 | ✅ 相同 |
| 下载器 | ST-Link V2 | ST-Link V2（仍可用） | ⚠️ 带一条无害报错，见 6.3 |

## 3. 替代成本量化

### 3.1 硬件成本：**零改动** ✅

Pin-to-Pin 兼容 → 现有洞洞板**接线无需改动**，直接换板即可。

### 3.2 软件成本：**1 行代码** ✅

| 项 | 实测结果 |
| --- | --- |
| 平台宏 / 条件编译 | **0 处** |
| 平台分支代码 | **0 处** |
| 必须新增的代码 | **1 行** —— `HAL_ADCEx_Calibration_Start(&hadc1)` |
| 必须重测的参数 | 12 个摇杆标定常量（**由 ADC 校准引起，与平台无关**，见 6.1） |

> **说明**：这一行并非"GD32 才需要" —— 它是**原固件本来就缺**的（从未调用 ADC 自校准），两个平台都受益。详见 [`porting-report.md`](./porting-report.md) §4.2。

### 3.3 工具链成本：**可完全复用**

* Keil 工程、源文件列表、编译选项、优化设置**全部不变**；
* 唯一的工具链现象：ST-Link 报 `Error: Not a genuine ST Device! Abort connection.`（不阻断烧写与校验）。

### 3.4 总成本汇总

| 维度 | 成本 | 说明 |
| --- | :---: | --- |
| 硬件改动 | **0** | Pin-to-Pin |
| 软件改动 | **1 行** | ADC 自校准 |
| 平台适配代码 | **0** | 无宏、无分支 |
| 参数重测 | 12 个常量 | 由 ADC 校准引起，非平台差异 |
| 工具链迁移 | **0** | 同一工程 |
| **综合迁移成本** | **极低** | 一次编译烧写即完成 |

## 4. 替代后的功能与性能对比

（数据来源：[`porting-report.md`](./porting-report.md) §3 / §4）

| 维度 | 结果 | 判定 |
| --- | --- | :---: |
| 功能项 | USB 枚举 / 16 按钮 + 6 轴 + POV / 8 按键 / 双摇杆 / SW1·SW2 —— **6/6 一致** | ✅ |
| 端到端延迟 | STM32 `0.52 / 0.97 / 1.02 ms` vs GD32 `0.53 / 0.98 / 1.01 ms`（差异 ≤ 一个直方图桶宽 10 µs） | ✅ |
| 延迟 `min` | **两平台完全相同（26 µs）** | ✅ |
| 延迟 `P99` | 两平台均 **≈ 1 ms**（一个扫描节拍） | ✅ |
| ADC 读数（加校准后） | 差异 **≤ 4 counts**（静置噪声级） | ✅ |
| ADC 满量程 | 两平台均达 **4095** | ✅ |
| 静置噪声峰峰 | STM32 `4/4/4/3` vs GD32 `5/4/4/7` counts | ✅ |
| 稳定性 | `tx_fail = 0`；`tx_dropped` 占 **0.73%**（属固有相位竞争，非平台问题） | ✅ |
| 时钟树 | 两平台 `SystemCoreClock = 72 000 000` | ✅ |

**结论**：**功能一致、性能一致**（差异均落在测量分辨率/噪声之内）。

## 5. 替代收益

### 5.1 供应链韧性

同一套硬件设计可在这两个供货渠道之间切换，**降低单一供应商风险**；对已量产产品意味着"断供时无需重新设计板子"。

### 5.2 成本 ⬜（待补实际报价）

> ⬜ 需补充：两型号的**批量报价 / 交期**对比（建议记录渠道、数量、日期，便于复现）。

### 5.3 性能余量（潜在升级空间）

GD32F103 的主频上限为 **108 MHz**（ST 同类为 72 MHz）。本项目**未启用**它（USB 需精确 48 MHz 时钟，72 MHz 是最稳配置），因此该余量可作为**后续功能扩展的裕度**（如：更高频率的传感器采样、更复杂的滤波算法、振动马达的更高分辨率 PWM）。

### 5.4 生态与可获得性

* 引脚与寄存器高度兼容，社区移植资料丰富、风险可控；
* 国产渠道供货稳定，配合国产 Flash（如 **GD25 系列 SPI NOR**）可进一步形成**国产化组合方案**。

## 6. 替代风险与缓解

| # | 风险 | 等级 | 现象 | 缓解措施 |
| :---: | --- | :---: | --- | --- |
| 6.1 | **ADC 未校准偏移**（真实缺陷，两平台都有） | 中 | 两平台静置中心相差最多 **104 counts**、满量程差 62 | 迁移时**必须**实现 ADC 自校准（1 行），并**重测所有标定参数** |
| 6.2 | **"只看功能不看数据"的方法论风险** | **高** | 功能完全正常，但性能/精度已悄悄退化 | 建立**量化验收判据**（见第 7 节），不接受"看起来一样" |
| 6.3 | 烧写工具的正版检测报错 | 低 | ST-Link 报 `Not a genuine ST Device` | **忽略**（不影响烧写校验）；或改用 GD-Link / J-Link |
| 6.4 | 长期稳定性未验证 | 中 | — | 补 **≥ 72 h** 老化测试（本项目既有交付标准） |
| 6.5 | Flash 等待周期 / 主频上限差异 | 低 | 本项目**未触发**（72 MHz 下功能与延迟均正常） | 若将来启用 108 MHz 或改动时钟树，**必须重跑全部量化对照** |
| 6.6 | 标定参数随板/随器件漂移 | 低 | 换摇杆或换板后常量失效 | 终局方案：**标定值运行期写入 + 存 Flash**（双备份 + CRC32），每块板自带标定 |

## 7. 可复用的迁移验证方法（本报告的工程价值）

本次验证沉淀出**三条判据**，可直接用于任何"同类 MCU 平台迁移"的验收：

| # | 判据 | 用法 | 本次结果 |
| :---: | --- | --- | --- |
| 1 | **`min` 值跨平台比对** | 最短路径耗时最灵敏 —— 它一致，基本可断定代码路径耗时一致 | 两平台均 **26 µs** ✅ |
| 2 | **延迟差异 vs 直方图桶宽** | 差异 ≤ 桶宽 → 落在**测量分辨率内**，即"测不出差别"，不要当成真实差异 | 差异 ≤ **10 µs** = 1 桶 ✅ |
| 3 | **`tx_dropped` 增速作运行期探测器** | 静止时看增速：**≈0/s** = 主机按 1 ms 取；**≈800/s** = 主机改成 5 ms 取（端点参数退化） | ≈7/s（0.73%）✅ 正常 |

**方法论要点**：**控制变量** —— 同一份源码、同一套接线、同一测量方法、同一按键次数，唯一变量是主控芯片。
并且**先量化、后结论**：本次"ADC 差异"正是靠量化对照才发现的（功能层完全看不出来）。

## 8. 结论与建议

### 8.1 可替代性评级

| 维度 | 评级 | 依据 |
| --- | :---: | --- |
| 引脚 / 封装兼容 | **完全兼容** | Pin-to-Pin，硬件零改动 |
| 软件迁移成本 | **极低** | 1 行代码、0 平台宏 |
| 功能一致性 | **一致** | 6/6 项通过 |
| 性能一致性 | **一致** | 差异落在测量分辨率 / 噪声内 |
| 工具链兼容 | **完全兼容** | 同一 Keil 工程 |
| **综合可替代性** | ✅ **高（推荐替代）** | 迁移成本极低，无功能与性能退化 |

### 8.2 适用与不适用场景

| 场景 | 判断 |
| --- | --- |
| 已基于 STM32F103 的存量设计、追求供货韧性 | ✅ **非常适合**（Pin-to-Pin + 一行代码） |
| 对 ADC 精度敏感的应用 | ⚠️ **必须先做 ADC 自校准 + 逐项标定对照**（本次教训） |
| 需要 >72 MHz 主频 | ⚠️ 需另行验证时钟树与 USB（48 MHz）约束 |
| 对长期可靠性有硬性要求 | ⚠️ 需补 ≥72 h 老化与高低温等测试 |

### 8.3 建议

1. **推荐替代**：迁移成本与风险均极低，建议将 GD32F103C8T6 作为**并行备选平台**长期维护（同一份源码、同一工程）；
2. **迁移标准动作**：① 补 ADC 自校准 → ② 跑第 7 节三条判据 → ③ **重测全部标定参数** → ④ 补长期老化；
3. **长期工程化**：把标定参数做成**运行期写入 Flash**，使同一固件可服务多块板/多批次器件。

### 8.4 遗留验证项

1. **≥ 72 h 长时间运行稳定性**（当前仅验证到 ≈134 秒量级）；
2. 无线（2.4G）通路未纳入本次范围；
3. GD32 的 108 MHz 主频余量未启用、未验证；
4. ⬜ 两型号批量报价 / 交期数据（见 5.2）。
