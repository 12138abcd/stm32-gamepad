# 长时间实测报告（2026-10-19 → 2026-10-20）

> **一句话**：12 键手柄连续跑 6 小时，**固件侧无异常**；中途出现的 View 键失灵被定位为**外部软件注入冲突**（与手柄无关），RT 的一次异常**偶发、未复现**。

---

## 一、测试环境

| 项 | 值 |
| --- | --- |
| 主控 | STM32F103C8T6（蓝板，72MHz） |
| 输入 | 十字键 4 + 面键 A/B/X/Y 4 + 肩键 LB/RB + View/Menu + 双摇杆（L3/R3 可按下）+ 双扳机（直滑电位器，模拟） |
| 固件 | 无线 A 路线第 4 步的 `p2p` 测试固件（接收端） |
| 连接 | USB HID（9 字节报告，1ms 轮询间隔） |
| 系统 | Windows 10 |
| 应用 | 某 Unity 引擎游戏（新 Input System） |

## 二、测试方法

- **连续操作 6 小时**，包含游戏内操作 + 桌面/浏览器切换
- **每 30 分钟**抽检一次 `joy.cpl`（Windows 游戏控制器面板）：12 个按键 + 6 个轴是否正常
- **出问题时立即记录**：哪个键、什么现象、`joy.cpl` 里是否正常

## 三、结果

### 前 2 小时：全部正常 ✅

**12 个按键、6 个轴（双摇杆 + 双扳机）全部正常响应**，无丢键、无漂移、无抖动。

### 2 小时后：两处异常

| 现象 | 描述 |
| --- | --- |
| **View 键响应变差** | 从"偶尔漏一次"发展到"约按两次才响应一次" |
| **RT 扳机偶发异常** | 某次"缩小地图"操作时，游戏里传送点被意外高亮；**准备分析时效果消失，无法复现** |

## 四、排查过程

### 第 1 步：先看硬件

- **View = `PA9`**（GPIO 输入 + 内部上拉）、**RT = `PB0`**（ADC_IN8）
- **两者没有任何共用硬件**（一个是数字输入、一个是模拟采样）
- 但**同时出问题** → 指向**共性原因**（温度 / 电源 / 软件），而不是某个焊点

### 第 2 步：分离变量 —— 关闭游戏侧的 DLL 注入器

该游戏进程里常驻一个 **DLL 注入器**（`winhttp.dll`，用于加载游戏插件），它会和 **Steam Input** 抢同一个进程的注入权。

**操作**：`winhttp.dll` → `winhttp.dll.off` → **从 Steam 启动**（不要双击 exe，Steam Input 要靠 Steam 拉起才生效）→ 重测。

### 第 3 步：View 恢复正常 ✅

**View 键不再失灵** → 证明**与手柄硬件、固件都无关**，是**软件侧的注入冲突**。

### 第 4 步：RT 无法复现

重测期间 RT 的那次异常**没有再次出现**，无法进一步定位。

## 五、结论

| 项 | 结论 |
| --- | --- |
| **View 失灵** | **软件侧注入冲突**（游戏进程的 DLL 注入器 vs Steam Input），**与手柄无关** ✅ |
| **RT 异常** | **偶发、未复现**，证据不足以定性（可能是游戏本身的高亮机制，也可能是 ADC 瞬时漂移） |
| **手柄固件** | **6 小时连续运行无异常**（前 2 小时全正常；后 4 小时的 View 问题已证明是软件侧）✅ |

## 六、对固件的启示

1. **手柄侧无问题** —— 12 键 + 6 轴在 6 小时内全部正常（除外部软件干扰外）
2. **长时运行无内存/计数问题** —— 6 小时 = 21600 秒，`uint32_t` 计数器远未溢出
3. **下次长测加诊断量** —— 若再出现类似现象，先把"按键原始电平 / `adc_buf[]` 原值"暴露到调试器，区分"读不到"和"读到了但软件不认"
4. **最重要的教训**：**外部软件干扰会伪装成硬件故障** —— **分离变量（先关掉可疑软件）永远是排查第一步**，比拆焊点、换线快得多
